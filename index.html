Security Model

Defense in depth — four independent security layers from prompt to result.

🛡️

Layer 1 — Prompt Guardrails

Heimdall · :8001

Every prompt is inspected before reaching any AI model.

KEYWORD — blocks known destructive terms (DROP, DELETE, TRUNCATE…)
SEMANTIC — embedding similarity to known threat patterns
THRESHOLD — configurable similarity score ceiling
CONTEXT — fail-safe: blocks if user has no domain access
🔒

Layer 2 — Data Access Control

SAGE · :8003

Security policies enforced at SQL generation time, not as an afterthought.

Row-Level Security (RLS)
Users only see rows matching their security group. India rep → only Indian data.
WHERE country IN ('India') -- auto-injected
Column-Level Security (CLS)
Restricted columns excluded from generated SQL based on user permissions.
-- profit_usd excluded (restricted)
✅

Layer 3 — SQL Validation

VALKYRIE · :8004

Generated SQL verified before it ever surfaces to the user.

Syntax — valid PostgreSQL
RLS — filter expressions present in WHERE clause
CLS — restricted columns absent from SELECT
Semantic — LLM verifies intent matches the SQL
Correction loop: VALKYRIE calls SAGE /sql/correct per failed query and re-validates (max 2 rounds).
👤

Layer 4 — Identity & RBAC

Backend · :8000

JWT-based auth with role-based access and fine-grained security groups.

User Role
Chat + My Profile only
Limited
Admin Role
Full platform access
Full
Security Groups — fine-grained data access. Each user belongs to groups that define allowed domains, RLS filters, and CLS column exclusions.
